The system

The Conviction Research System is a financial model built for recursive self-improvement, with a person holding every gate. It grades its own calls against the filings that arrive after them, and its rules change only on that evidence, creating a loop.

It uses agent bots to pull and read primary sources — SEC and foreign filings, market data, company transcripts — and turns them into conviction scores in which every number traces back to the document it came from. It also keeps a selective roster of people worth tracking — writers, executives, investors — chosen for making calls that are dated and checkable, and kept only while their record holds.

Every call the model makes is written down with its date, its thesis, and the condition that would prove it wrong. The same ledger that grades the people it tracks grades the bots, the drafting model, and the pipeline, and no rule changes without a person ruling on it.

Tokens processed are the four API usage fields Claude Code records per assistant message (input, output, cache creation, cache read), summed by UTC day — cache reads included and shown in the bar. Automated runs are counted by type and by day from the logs: Code sessions are main transcripts dated by their first message; scheduled runs are the daily sweep log's run entries (a sweep entry per daily run, and filing-watch entries for hits plus the once-a-day heartbeat rather than every poll; the crypto recorder writes no entry); unattended builds are MANIFEST-build files by date; sub-agent forks are Agent tool calls on assistant records. Payloads landed are register rows. Documents pinned are SHA-256 pin records across the EDGAR, DART and EDINET lanes. Filings read are pinned filings that carry a read record — a ratified constraint-map assessment or a completed hand-read sheet; draft sheets never count. Claims graded are management guidance claims with a HIT or MISS; voice calls graded are seal-register rows carrying a grade. Claude Code sessions only; mentor conversations not counted.
